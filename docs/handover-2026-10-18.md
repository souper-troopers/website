## 4. How the site works now (things that surprise newcomers)

- **Pages swap in place** (Astro `ClientRouter`, since 17 October). A bundled `<script>` runs once
  per visit, not per page: page setup must go through `onEveryPage()` in `src/lib/page-load.ts`, and
  inline scripts that set up a page need `data-astro-rerun`.
- **Contact, Save our Hub and the status page load in full** (`<Layout fullReload>`, listed in
  `FULL_RELOAD_PATHS`): Netlify's reCAPTCHA only renders on a real load. They are never fetched by
  script, and links to them skip the router.
- **The main pages are kept in memory** (`src/lib/warm-pages.ts`) with their banner photos
  preloaded; Astro's own prefetch stays **off** (it blanked pages in Safari in September).
- On iPhone and iPad the page fade is off (`@supports (-webkit-touch-callout: none)`).
- Every page's banner is `PhotoHero.astro`; its tint is measured for contrast per photo.
- Visitors in Cape Town are served from Netlify's edge in São Paulo (~0.2s per request); Cloudflare
  in front was judged overkill.

## 5. How to work on it

- `npm run build` (typechecks first) and check the exit code. Preview with
  `npx astro preview --port 4400` - the dev server has repeatedly lost `sharp`.
- Screenshot at **390 and 1280**; Playwright screenshots go under `.playwright-mcp/` in the repo.
- Hero/banner changes: re-run the contrast check (`scripts/check-hero-contrast.playwright.js`,
  pointed at port 4400).
- **iPhone-only bugs:** ask the user for a screen recording (Control Center -> Record) and step
  through it frame by frame (a Swift/AVFoundation frame grabber; there is no ffmpeg or Xcode here).
  Playwright's WebKit does not reproduce real iPhone behaviour.
- Update `AGENTS.md` and, for client-facing changes, `src/pages/changelog.astro` as part of shipping.
- Messages for Kerry or Shan: plain language, link to the specific status-page question when there
  is one, and give the text ready to paste.
